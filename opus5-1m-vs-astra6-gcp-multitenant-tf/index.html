A Kriya lab slot · 11 September 2026

Opus 5 1M vs
GPT-6 Astra

Task: from an identical brief that states requirements but not topology, write the Terraform for a multi-tenant, two-sided platform on GCP. Three rounds: build, one self-repair pass from raw tool output, then review the other arm's repo.

Trust-model deviation. Every other lab here discards the models' generated code. This one keeps it: both repos are public, Apache-2.0, with a PROVENANCE.md, so anyone can re-run the judge or re-grade the findings. Nothing was applied to GCP; neither arm had credentials.

Setup

Both arms ran headless and non-interactive inside their own fresh git repo containing only BRIEF.md (byte-identical, checksum-verified). The rubric was fixed and committed before the run and never entered either repo. Model identity comes from telemetry, not self-report: claude-opus-5[1m] via Claude Code, gpt-6-astra via Codex CLI 0.153.4.

Interpretation: the build itself does not separate these models. Both passed fmt, init, validate and tflint on the first draft, both failed only the unannounced checkov scan, and both cleared it in one repair pass with no suppressions. Each lost one different objective point: Opus pinned providers with ranges where the brief said explicit versions; Astra shipped no child modules. The gap opened in round 3. Astra's review of the Opus repo produced 15 verified defects, including a project-wide cloudsql.client grant with no IAM condition and a dead-letter topic with no subscriber. Opus's review of the Astra repo produced 3 verified low-severity items, and its one high-severity claim rested on a GCS restriction the grader could not confirm still exists. The architecture section moved one point on blast radius for the same IAM finding. Cost and speed are reported, not scored: the harnesses differ, and Codex CLI reports no dollar figure.

What separated them

Repair styleGiven the same kind of checkov output, Astra fixed exactly what was listed. Opus fixed it and added a KMS module, customer-managed keys and 218 README lines. Both are clean; one grew the surface.
Review depthAstra read the whole Opus repo and found real defects in eventing, IAM conditions, alert filters and the offboarding runbook. Opus's review of the smaller Astra repo argued mostly with documented design choices.
Blast radiusAstra conditioned SQL roles on the tenant's own dedicated instance. Opus granted the role project-wide and relied on a manual REVOKE step for shared-instance CONNECT. Both scope secrets, buckets and topics per tenant.
Fixed in advanceBrief, rubric, prompts and judge config were committed before any model ran. The grader knew which arm was which; sections 1–4, 6 and 7 are machine-checkable or verified-by-reproduction, and section 5 is five yes/no questions.
